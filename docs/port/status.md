# BAP MoonBit Port Status

This repository is porting `.repos/bap` from OCaml to idiomatic MoonBit.

## Implemented

- `bitvec`: fixed-width bitvectors with normalization, bit predicates, unsigned and signed shifts, modular arithmetic, unsigned division/remainder, gcd/lcm/extended-gcd, concatenation, extraction, hexadecimal and BAP-style string literal parsing/formatting, and endian byte conversion.
- `regular`: printable helpers, deterministic digest wrappers, format metadata/registry support, and a prefix trie with `find`, `remove`, and longest-prefix matching.
- `graphlib`: persistent directed graphs with node/edge operations, successor/predecessor queries, DFS edge classification, reachability, reverse postorder, dominator-set and immediate-dominator computation, and dominance frontiers for SSA-style analyses.
- `types`: BAP-style `Word` wrapper over `bitvec`, value types, variables with BAP-style SSA index/base helpers, a BIL expression/statement AST with type inference, free-variable analysis, variable/expression substitution, scalar and byte-addressed memory expression evaluation, bounded statement execution over BIL state, focused BIL simplification with constant store-chain load folding, statement-level constant propagation with static branch facts, jump-aware branch conservatism, definitely-skipped loop facts, BAP-style loop propagation regressions, dead virtual assignment pruning, and a bounded fixpoint optimization pipeline with translated BAP-style full-pipeline regressions, plus an initial IR term layer with tids, attributes, program/sub/block containers, defs, phis, jumps, calls, labels, arguments, expression traversal/free-variable/substitution helpers, whole-program IR traversal/find helpers, BAP-style block definition sequence/edit/split utilities, local subroutine CFG helpers over direct jumps, interrupts, and call returns, direct and resolver-backed callgraphs over program terms, phi-aware block liveness over reachable subroutine CFGs, and semipruned SSA conversion with dominance-frontier phi insertion and dominator-tree renaming.
- `knowledge`: typed names, partial orders, monotone domains, class/slot metadata, object allocation, and fact tables that merge values through domain joins.
- `core_theory`: symbolic sorts, typed values, variables, effect lattice values, labels, source/compiler/program-unit metadata, target metadata with inheritance/matching helpers, immutable metadata update helpers, metadata enum parsing/formatting, alias-origin tracking, conservative register role helpers, broad BAP-style common architecture target declarations, and a target registry/lookup layer.
- `memory`: byte-addressed memory regions with rebasing, views/ranges, endian-aware word loads and stores, contiguous merges, hexdumps, and a basic interval `MemMap` with lookup/intersection/dominator queries, min/max bindings, and exact/interval removal helpers.
- `native_io`: native-target file reading behind a small package boundary, with explicit non-native stubs so pure packages keep checking on wasm/js/llvm.
- `image`: image metadata over `memory`, including target/arch accessors, target-derived address size, stored or target-derived Ogre specifications, BAP-style `of_bigstring`/`of_string`/`from_spec` constructor aliases over byte loaders and Ogre docs, segments, sections, symbols, memory maps, symbol/section/segment lookup, multi-segment symbol memory chunks, endian-aware `Image.words` extraction, a MoonBit backend registry with description/extension/priority discovery metadata that loads bytes into `(Image, warnings)` by explicit backend, filename extension, or native file path, an Ogre document parser with declaration/fact validation and scalar normalization, and raw/spec-style Ogre-to-image conversion for entry, target metadata, endian, segment/mapping, code-region, section, and function-symbol facts.
- `project`: project container over `core_theory`, `types`, `memory`, and `image`, with target/arch/program/memory/symbol/image/disassembly state, image/library specification accessors, typed storage tags over string-backed storage, whole-storage replacement, including bitvector tags and lossless string-, int-, uint64-, bool-, and bitvector-array tags, memory tagging, BAP-style string substitution for memory annotations over section/symbol/block/address placeholders, symbol-table replacement, program mapping, library records with program-unit metadata, project input constructors/loaders with code/data memory union and symbol propagation, extension/priority metadata plus image-backend fallback/discovery, BAP-style checked raw byte/string/native-file/binary input, file convenience loading, filename/native-file-based selection, disassembly driver registration/discovery/application, named dependency-aware pass registry with explicit/autorun execution, run-once passes, pass run-count telemetry, typed project collators with registration/discovery for comparing alternative project versions, and typed analysis argument parsers with BAP-style bitvector literals and named analysis registry/application.

## Next Packages

- Expand `core_theory` with the full BAP knowledge registry, source/compiler/program-unit integration with facts, full alias provenance, and deeper architecture-specific target metadata.
- Expand `types` with fuller BIL normalization and broader memory-aware optimization passes, richer IR visitors and control-flow semantics, additional SSA/data-flow transforms over the term layer, SSA cleanup/destruction helpers, richer indirect call resolution integrations, and the remaining tests translated from `.repos/bap/lib_test/bap_types`.
- Expand `image` with richer file-format backends and deeper loader metadata.
- Expand `project` with concrete disassembly driver implementations, real `$asm`/`$bil` substitution output, and higher-level project orchestration.

## Porting Defaults

- Use `Bytes`/`BytesView` for binary payloads and file-format input.
- Use checked `suberror` plus `raise` instead of OCaml exceptions and `Or_error.t`.
- Keep pure packages target-agnostic; isolate native stubs behind native-only packages.
- Prefer behavior-level compatibility over OCaml module-shape compatibility.
